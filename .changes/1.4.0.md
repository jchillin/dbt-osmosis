## 1.4.0 - 2026-05-05
### Added
* Add opt-in controls for high-friction column inheritance workflows.

- Add `skip-inherit-descriptions` so projects can keep empty downstream column descriptions instead of inheriting upstream text when that text may be semantically wrong (#326).
- Add `skip-inheritance-for-meta-keys` so selected upstream column `meta` keys such as package-specific `expression` or `doc_blocks` values can be excluded while other metadata still inherits (#333).

### Changed
* Align the supported runtime, public import surface, and top-level docs with the code that is actually exercised.

- Restore open-ended dbt Core packaging support (1.8+) and update CI/local/docs language so the project no longer falsely claims support stops at 1.10 just because the DuckDB fixture matrix is explicit through currently published compatible lines.
- Add a latest-dbt-core compatibility path that installs the package with dbt Core 1.11 plus the latest published DuckDB adapter, runs basedpyright, performs `dbt parse`, and executes the full pytest suite.
- Collapse broad `dbt_osmosis.core` re-exports so `dbt_osmosis.core.osmosis` remains the single compatibility facade and internal code imports concrete submodules directly.
- Rework bootstrap detection so project-local profiles and Fusion compatibility are derived from project evidence instead of PATH-only guesses.
- Rewrite README and Docusaurus reference pages to enumerate the shipped CLI families, formatter/config behavior, current tooling prerequisites, and DuckDB-only exercised fixture coverage.
- Record the narrowed dbt installation support window and cleaned-up core public API surface in repository guidance and documentation memory.
- Refresh docs and Python dependency groups from passing Dependabot PRs (#384, #389, #390, #391).

### Fixed
* Repair correctness and trustworthiness issues across YAML management, SQL flows, optional integrations, and CI support tooling.

- Preserve unmanaged schema YAML sections when `yaml refactor` restructures the last managed model/source/seed out of a file, preventing loss of sections such as `semantic_models`, `databricks-tags`, and future top-level dbt metadata (#306, #329).
- Keep dirty YAML buffers pinned until commit so large refactors cannot silently lose earlier edits, and make source bootstrap plus restructuring write tracking/reload behavior truthful.
- Honor `scaffold-empty-configs` from dbt project `+dbt-osmosis-options`, not only from the CLI flag, when YAML sync decides whether to retain empty placeholders (#328).
- Align schema parsing and validation with supported YAML shapes, including nested sources, top-level `data_tests`, seed columns, and `raw_content` validation.
- Fix sync and inheritance edge cases for versioned models, source matching, progenitor overrides, and external-node selection.
- Prevent trailing whitespace when nested column descriptions wrap near the configured YAML width (#311).
- Stop schema diff rename detection crashes, ensure plain SQL compilation always cleans up temporary manifest nodes, make staging dry-run paths side-effect free, and lint only compiled model SQL instead of raw manifest entries.
- Allow pattern-based test suggestions to work without the OpenAI extra, honor LM Studio and Ollama default settings, normalize Azure AD scope handling, and replace the workbench AI panel's fake generate/apply behavior with a truthful unavailable state.
- Make `dbt-osmosis[workbench]` install the IPython dependency required by `ydata-profiling`, catch transitive workbench import failures during CLI preflight, and keep OpenAI optional for workbench startup (#305).
- Make fixture dbt commands fail fast, retire the unexercised PostgreSQL fixture branch, refresh manifest freshness checks, isolate shared YAML caches in suite-sensitive tests, apply CI-required Ruff formatting, and bump the gitleaks pre-commit hook to avoid the older wasm panic in CI.
